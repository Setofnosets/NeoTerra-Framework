# Neo Terra Framework

A self-contained [SillyTavern](https://github.com/SillyTavern/SillyTavern)
extension for the Neo Terra superhero setting. It turns each chat into an
independent season timeline: a world is constructed from a season definition,
kept in a structured `WorldState`, narrated by the Director, and updated by
small schema-constrained agents that never free-write state.

**Minimum SillyTavern:** 1.19.0  
**License:** MIT  
**Runtime dependencies:** none (no CDN, no npm install, no other extension)

---

## Features

- **Six entry points** — S1, S1Dark, S2, S3, S4, and Sandbox. S1Dark is the
  alternate **Villain POV** season (play as Carol Fate / Bleeding Heart); S5
  appears as a disabled "auxiliary data present — coming later" card.
- **Player identity** — custom persona by default, or "Play as" a canon
  character from the current roster (any registry character in Sandbox, with a
  persistent non-canon warning).
- **In-chat scene output** — season start and travel post deduped Neo Terra
  narrator frames into the same chat, including a "your move" kickoff card and
  travel arrival/encounter prose. World state stays in the prompt, not the
  transcript. See [docs/scene-output.md](docs/scene-output.md).
- **Deterministic encounters** — arriving where hostiles are present records an
  encounter in scene state and offers explicit **Engage / Talk / Avoid**
  actions; Engage starts the deterministic combat flow.
- **World state** — one versioned `WorldState` document per chat, written only
  through typed events. Per-chat storage, per-swipe snapshots, and a WAL guard
  against reloads mid-pass.
- **Agents** — every call is validated JSON; failures are logged, never
  applied. **Wired today:** State Tracker (every assistant turn), Storyline
  Tracker (its own cadence), Cast Director (travel/arrival and scene cadence),
  Lore Agent (every 10 turns or act change, feeding the Journal), Continuity
  Auditor (act boundaries), Choices Agent (opt-in), the Epilogue Agent (behind
  `ending.dynamic`), Bad End Detector + panel (opt-in), the Form Architect
  (missing-form profiles on transform), and the Architect season-start pass
  (opt-in via `agents.architect.seasonStart`). The agent log opens from any
  error toast or `/neoterra log`.
- **Portraits** — a generated avatar manifest, a per-user **Sync portraits**
  action, and resolution from installed SillyTavern cards. Ambiguous short names
  fall back to initials instead of swapping portraits. See
  [docs/avatars.md](docs/avatars.md).
- **Guests** — any registry character can guest in any playable season after a
  visible warning and a mandatory acknowledgment. Guests keep the season world;
  dependent canon beats adapt rather than fail.
- **Living forms** — alternate forms swap the profile (appearance, attire,
  abilities, traits, likes, dislikes, goals, notes) while preserving resources,
  status, relationships, and manual edits. Missing forms are generated by the
  Form Architect, stored per chat, reviewed in the Codex, and exportable.
- **Canon Beat Ledger** — flexible completion, adaptation, short-circuiting,
  soft deadlines with escalating consequences, and a recorded villain victory.
- **Villain victory** — a ~5-paragraph epilogue, then **Resistance**, **Join the
  villain**, or **End here**. Both continuations rewrite the world into a
  post-victory arc with new beats.
- **Bad ends (opt-in)** — death, identity loss, autonomy loss, permanent
  corruption, imprisonment, and retirement. Deterministic predicates first;
  stored epilogues; continue as the character or as someone else.
- **Optional CYOA choices** — 4 context-derived choices by default, labels up
  to 100 characters, plus a completely independent tactical combat-choices
  setting.
- **Content gate (off by default)** — `full`, `reduced`, `mature-only`,
  `strict`, with per-character and per-player hard limits that always win.
- **SVG map** — 36 districts, 12 bridges, and 22 key locations extracted from
  the authoring SVGs into GeoJSON, rendered with vendored Leaflet. Travel uses
  the bridge graph, not straight-line distance. The editor changes overrides,
  never the SVG art.
- **Combat resolver** — seeded `d20 + modifiers` into five bounded tiers, no HP
  attrition, with `/neoterra-roll` and a registered dice function tool.
- **Codex and settings** — searchable cast, live state, form lineage, bad-end
  badges, "Play as", agent routing/prompts/cadence, token budgets, world
  export/import, and card-import override generation.
- **Living city (V1.1)** — a fiction clock with a one-click time brake, an
  off-screen world tick, a pacing director, an opt-in in-world newspaper, fog
  of war, a **Relations** graph tab, and a generic **Domain** sensorium for
  villain-POV seasons. All state lives under `WorldState.flags.*`; every
  feature can be switched off without touching a chat.
- **Experience layer (V1.2)** — a persistent, collapsible HUD, floating
  Map/Codex/Relations/Journal windows, cinematic scene cards, a turn-progress
  chip with state-delta toasts, a Journal/recap, a first-run wizard, and a
  keyboard command palette.
- **Living world (V1.2)** — Cast Director arrivals/departures, Lore recaps,
  act-boundary continuity findings, the opt-in Bad End panel, an agent log
  drawer, optional season-start Architect passes, optional side beats,
  deterministic downtime actions, and season-specific ending-pilot epilogues.

> **Experience audit:** [docs/experience-audit.md](docs/experience-audit.md)
> records the 2026-11-18 audit of the in-play experience, the intended-vs-actual
> matrix, every known gap with a file:line anchor, and the remediation plan.
>
> **Manual QA:** [docs/qa.md](docs/qa.md) is the release checklist, including
> mobile at 390×844, content gate, export/import, and agent-failure paths.

## Install

1. Clone or copy this folder into SillyTavern's third-party extensions
   directory:

   ```bash
   cd SillyTavern/data/default-user/extensions
   git clone https://github.com/Setofnosets/NeoTerra-Framework.git
   ```

   The resulting path is
   `SillyTavern/data/default-user/extensions/NeoTerra-Framework/`.

2. Reload SillyTavern (or refresh the browser). No build step and no
   `npm install` are required for the extension to run.
3. Open the **Extensions** settings drawer and confirm **Neo Terra Framework**
   appears. Use the top-right **Neo Terra** button or `/neoterra` to open the
   shell.

The map loads its assets from `vendor/leaflet/`. It works offline and does not
read Leaflet from a CDN, npm, or another extension's global.

## First run

1. Open the shell and choose a season. Each card shows the era, premise, player
   role, main threat(s), and cast count.
2. Choose an identity: **custom persona** or **play as a canon character**
   (S1Dark preselects Carol / Bleeding Heart). A canon radio carries its
   registry id directly; choosing it and pressing **Begin** is enough — the
   old "create a custom persona first, then Play as" workaround is gone.
3. The extension seeds the world deterministically, materializes a chat-scoped
   world book, selects the Director card, and posts an opening scene frame plus
   a **"Season started / You are / Goals / Current situation / Your move"**
   kickoff into the chat. The shell closes and focuses the input.
4. Play normally. State Tracker runs every assistant turn; Storyline runs on
   its own cadence (default every six turns or on a location change); the Cast
   Director runs on travel/arrival and on its scene cadence; Lore runs every ten
   turns or on an act change and writes the Journal recap; the Auditor runs at
   act boundaries. All cadences and enable flags are configurable. Every
   assistant turn advances the clock, runs the off-screen world tick and pacing
   analysis, and refreshes the map before CYOA choices are requested.

The chat is the primary surface: travel posts a `Location changed: X → Y`
arrival frame (with the encounter, if any), and a small action bar offers
**Engage / Talk / Avoid** when hostiles are present. World state is never
copied into the chat; it reaches the model through the generate interceptor.

World state is stored in `chatMetadata.neoterra`, so two chats with the same
season are independent timelines.

## Canon beats and deadlines

Each season declares a **Canon Beat Ledger**. A beat has an act, eligibility
conditions, a completion predicate, flexibility (`strict`, `adaptable`,
`optional`), a soft deadline, a declared consequence, and rewrite hints. The
Storyline Tracker may:

- resolve a beat whose predicate the observed events satisfy;
- emit a setup nudge for the next eligible beat;
- mark a beat `deferred` or `adapted`, recording `adaptedFrom` / `adaptedTo`;
- mark an impossible beat `short-circuited` and re-plan the next act.

Missing a soft deadline never blocks play; it makes the world worse according
to the beat's declared consequence. Beat pressure is configurable
(`off`, `generous`, `standard`, `harsh`, default `standard`). If the season's
final deadline passes, the main threat achieves a complete **villain victory**,
recorded once. Early villain defeat is a legal win and is recorded as a
divergence, not reversed. See [docs/canon-beats.md](docs/canon-beats.md).

## Villain victory and post-victory play

When the final deadline fires (or the main threat reaches its terminal stage),
the Epilogue Agent writes a ~5-paragraph epilogue grounded in `WorldState`:
who won, how, cast fates, faction control, and the player's status. The ending
fires once, is cached, and is not regenerated on reload.

The player then chooses:

1. **Resistance** — an underground movement with reduced resources and new
   resistance beats.
2. **Join the villain** — serve the victor: defeat the resistance, govern
   captured districts, conquer further places, or act as an enforcer. Join is
   state-aware (always available to villain/corrupted/brainwashed players,
   plausible for coerced heroes).
3. **End here** — stop at the epilogue; the world remains viewable.

Both continuations set `arc: 'post-victory'`, rewrite factions/threats, and
generate new beats with deadlines. See [docs/endings.md](docs/endings.md).

## Bad ends (opt-in)

`badEnds.enabled` is **false** by default. While off, no detection runs and
nothing is stored. When enabled, deterministic predicates are checked first
(stamina/willpower, corruption stage, captivity, permanent form rules) and the
LLM only confirms ambiguous cases. A confirmed state stores a short epilogue
and a persistent record keyed by `continuityKey`.

The player may continue as the bad-ended character when its state permits
agency (death only when `badEnds.allowDeadContinuation` is enabled), continue
as someone else, or end there. Records survive reloads, exports, and declared
reversals; they are never silently deleted. See
[docs/bad-ends.md](docs/bad-ends.md).

## CYOA choices (optional)

Exploration choices and tactical combat choices are two independent settings,
both off by default. When enabled, the Choices Agent reads recent context plus
`WorldState` and returns 2–6 choices (default 4). Labels are capped at 100
characters. Clicking a chip sends exactly that text through SillyTavern's
normal send path; "write your own" is always available.

Themes: `auto`, `heroic`, `villainous`, `romantic`, `noir`, `comedic`,
`tactical`, `lewd`. Combat choices default to `tactical` and are constrained to
actions the resolver understands (strike, defend, grapple, feint, skill,
retreat, surrender, talk down). See [docs/cyoa.md](docs/cyoa.md).

Choices are requested after a new assistant turn **after** the clock tick, the
State Tracker, the storyline pass, and the cast/map refresh, so the chips
reflect the updated state. The season opening frame and a travel arrival frame
also request choices when `cyoa.enabled` is on, even though no
`MESSAGE_RECEIVED` event fired for them.

## Settings handoff

The Neo Terra settings live inside SillyTavern's own **Extensions** drawer. The
shell's **Settings → Open settings panel** button closes the full-screen shell,
then opens the ST extensions drawer and expands/scrolls the Neo Terra panel
instead of silently scrolling a hidden element. Re-clicking with the drawer
already open leaves it open. If `#rm_extensions_block` or the Neo Terra panel
is missing, the Settings tab shows a visible status message and logs the
failure.

## Content gate

The global gate defaults to `full` (a byte-identical no-op). `reduced`,
`mature-only`, and `strict` transform every rendered block, card-profile section
in the Codex, and tracker prompt. Per-character and per-player hard limits are
layered on top and always win;
the global gate can only be as strict as those limits require. See
[docs/data-schema.md](docs/data-schema.md#content-limits).

## Map

The four `NeoTerra*.svg` layers are the authoring source of truth on a
**2048 × 1536** canvas. `tools/build-map.mjs` extracts districts, bridges, and
key locations by their `inkscape:label`, derives the bridge graph, merges
`data/map/overrides.json`, and writes `data/map/*` plus updated location
bindings. The runtime never parses SVG.

- Canvas: 2048 × 1536, y-down, origin top-left.
- Leaflet: `L.CRS.Simple` with `toLatLng({x, y}) => L.latLng(-y, x)`.
- Layer labels, not `sodipodi:docname`/`inkscape:export-filename`, decide layer
  membership.
- The base PNG (2017 × 1512) is stretched to the canonical box.
- Re-run `npm run build:map` after any SVG change. `--check` fails on missing
  layers, duplicate/empty labels, zero-area geometry, count drift, or stale
  generated files.
- The map tab and floating window fill the available height, and drag/resize
  stay inside the map host. Stored geometry from the old 1080×700 default is
  migrated to the taller default; custom sizes are preserved and re-clamped.
- `map.closeOnTravel` (default **`true`**) closes the shell after a successful
  travel so the chat shows the arrival frame. A rejected travel keeps the map
  open. The toolbar **×** also closes the shell.

See [docs/map-authoring.md](docs/map-authoring.md) and
[docs/scene-output.md](docs/scene-output.md).

## Data and extensibility

All season-specific content is data:

```
data/characters/index.json      # generated registry
data/characters/profiles.json   # generated card-section profiles
data/characters/overrides.json  # authored fixes and multi-actor cards
data/seasons/index.json         # generated season manifest
data/seasons/<id>.json          # season definition
data/locations.json             # named-location lore (2048×1536)
data/districts.json             # lore districts
data/factions.json
data/form-groups.json           # mutually exclusive forms
data/form-rules.json            # legal transformations
data/agendas.json               # off-screen faction/threat rates + rumors
data/map/*                      # generated geometry + authored overrides
data/schemas/*.schema.json      # published schemas
```

To add a season:

1. Drop character cards into `Chars/<Season>/`.
2. Add `data/seasons/<id>.json` with `id` matching the lowercase folder name.
3. Run `npm run build:data`. The season appears in the menu without code
   changes.

To add characters to an existing season, drop the cards into its folder and
re-run `npm run build:data`. Use the settings panel's **Import character
cards** drop zone to generate override entries for unusual cards; then merge
the downloaded file into `data/characters/overrides.json` and rebuild.

### Character profiles

`tools/build-data.mjs` parses each card's labelled `data.description`
sections into `data/characters/profiles.json` (keyed by the final registry id).
A non-empty live `WorldState` value takes precedence over the card; card text
fills the gaps and is shown in the card section when it differs from live state.
In existing chats, **Import card profile** (per character) and **Sync card
profiles** (header) fill only missing fields; they never overwrite live values
and are safe to run twice. New seasons seed the same text into empty state at
start.

Sensitive sections are parsed, not dropped. The Codex and the prompt renderer
apply `contentGate` and `contentLimits` at render time, so changing the setting
updates existing chats without rewriting stored state. Never hand-edit
`profiles.json`; run `npm run build:data`.

See [docs/adding-a-season.md](docs/adding-a-season.md),
[docs/data-schema.md](docs/data-schema.md#character-profiles).

### Troubleshooting

If the Characters tab shows **"The character codex could not be mounted."**:

- The host element carries the failure reason in
  `data-neoterra-codex-error` (inspect `[data-neoterra-codex-host]`).
- The browser console has a `Could not mount the character codex` warning with
  the same error.
- Report both. The Codex loads form groups/rules and the generated profiles;
  none of these should depend on the chat-scoped roster slice.

A missing `data/characters/profiles.json` is non-fatal: the Codex mounts with
live state only and season start still succeeds.

## The living city (V1.1)

These features share one rule: the world is still a single `WorldState`.
Nothing is authoritative outside it.

| Feature | Default | Turn it off |
| --- | --- | --- |
| Fiction clock + time brake | on | `clock.enabled: false` (restores V1: turns only) |
| Off-screen world tick | on | `worldTick.enabled: false` |
| Off-screen overlay feed | on | `map.showOffscreen: false` |
| Pacing nudge / cut | on | `pacing.enabled: false` |
| Newspaper | off | `newspaper.enabled: false` (no agent, no state) |
| Fog of war | off | `map.showFogOfWar: false` |
| Relations graph | available | no setting; the tab is read-only |
| Domain sensorium | automatic for a villain season with a `domain` block | omit `domain` or play a hero season |

Time flows at **one slot per turn** (`dawn → morning → afternoon → evening →
night`), so a day passes every five turns. Major scenes, beats, combat, and
intimate scenes can freeze fiction time with the top-bar time chip; while frozen
no date, story turn, off-screen tick, newspaper edition, or deadline escalation
occurs. `meta.turn` keeps moving; beat deadlines use `meta.storyTurn`.

- [docs/world-clock.md](docs/world-clock.md) — pace, `turn` vs `storyTurn`, the
  brake, and migration.
- [docs/world-tick.md](docs/world-tick.md) — `data/agendas.json`, rates, NPC
  movement, rumors, and caps.
- [docs/pacing.md](docs/pacing.md) — analyzer levels, the explicit cut, and
  `[NEOTERRA_PACING]`.
- [docs/newspaper.md](docs/newspaper.md) — editions, deterministic fallback,
  the agent, and the reader.
- [docs/fog-of-war.md](docs/fog-of-war.md) — exploration state, travel gating,
  and render modes.
- [docs/relationships.md](docs/relationships.md) — graph model, layout, filters,
  and keyboard behavior.
- [docs/sensorium.md](docs/sensorium.md) — the generic `domain` block and the
  Domain tab.

Every new prompt block has a settings toggle and a token budget
(`context.blocks.domain`, `tokenBudget.domain`, and the existing news/pacing
controls). The newspaper agent is the only new LLM call, and only when the
feature is enabled.

## Development

```bash
# Regenerate generated data
npm run build:data                 # data/characters/{index,profiles}.json + data/seasons/index.json
npm run build:map                  # data/map/* + data/locations.json bindings

# Validation
node tools/build-data.mjs --check  # cards, form groups, form rules, seasons, index freshness
node tools/build-map.mjs --check   # SVG geometry, graph, counts, generated-file freshness
node tools/map-coords.mjs --check  # named locations, optional draft validation
node --test tests/*.test.js        # unit and integration tests
npm run check                      # all of the above + syntax checks + smoke test
```

`tools/map-coords.mjs` is a **dev-only** fallback that asks a vision model for
coordinates of unlabeled/new sites. It never writes `data/locations.json`;
every proposal is human-verified. It requires `DEEPSEEK_API_KEY` for `--draft`.

No runtime npm dependencies are added. Node 20+ is only required for the
development tools and tests.

### Local dev install

When iterating on this repository against a running SillyTavern, point the
third-party install at the working tree instead of copying files. On Windows,
replace the copy with a directory junction (keep a backup first):

```bat
rmdir /S /Q "SillyTavern\public\scripts\extensions\third-party\NeoTerra-Framework"
mklink /J "SillyTavern\public\scripts\extensions\third-party\NeoTerra-Framework" "%USERPROFILE%\path\to\NeoTerra-Framework"
```

Replace the `%USERPROFILE%\path\to\NeoTerra-Framework` placeholder with the absolute
path of your clone. Then every save is served on the next page refresh, and repository-only files
(`plans/`, `tests/`, `tools/`) become visible to the static server without ever
being loaded by SillyTavern. Remove the junction with `rmdir` and restore the
backup to undo it.

## World export and import

The settings panel can export the current chat's world as a JSON bundle
(WorldState, season definition, roster slice, player identity, cast mode) and
import it into another chat. Import rebinds the state's `chatId` to the target
chat, preserves every character, beat, relationship, and bad-end record, and
re-materializes the world book on demand. Export/import does not include
SillyTavern chat messages.

## Known limitations

- V1 ships S1–S4 plus Sandbox. Season 5 has only auxiliary data and refuses
  entry with a clear message; the data format accepts a real S5 later.
- The `Others` / NeoHorizon setting is out of scope for V1.
- Combat is a narrative conflict resolver, not a tactical grid or HP system.
- No internet image fetching, card art generation, localization, multi-user
  sync, or plugin marketplace.
- Browser-only UI features (agent routing to a live SillyTavern connection,
  map rendering, world-book writes) cannot be exercised by the Node test suite;
  use the manual checklist in the plan for live QA.
- Imported character cards are not written to the repository by the browser;
  override generation is a download-and-merge workflow.
- PNG character cards are opt-in. `npm run build:data` reads `chara_card_v3`
  JSON cards from `Chars/<Season>/`; a `.png` with a JSON twin contributes its
  art, and a PNG with no twin is read from its embedded card chunk. See
  [docs/avatars.md](docs/avatars.md) and [docs/adding-a-season.md](docs/adding-a-season.md).
